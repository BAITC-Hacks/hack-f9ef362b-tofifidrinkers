# Аким на 5 часов — AI-симулятор управления городом

Команда **Tofifidrinkers** (`hack-f9ef362b-tofifidrinkers`). Хакатон HackAlem AI, спец-трек
**Astana Innovations**. MVP: распределить фиксированный виртуальный
бюджет (100 у.е.) между 5 районами, принять ровно 5 управленческих решений и получить итоговый
**Astana Quality of Life Score** с AI-объяснением.

> Данные синтетические. Результат — оценка внутри учебной модели хакатона, а не прогноз реальных
> последствий для Астаны.

## Архитектура

Next.js 16 (App Router, TypeScript) — фронтенд и бэкенд в одном приложении.

- `src/lib/data.ts` — датасет: 5 районов, 10 показателей, 14 мероприятий, синергии, несовместимости,
  бюджет и веса. Перенесено из «Датасет районов.docx» без изменений цифр.
- `src/lib/engine.ts` — расчётное ядро: `validateScenario` (проверка правил, ровно 5 решений, бюджет,
  максимум 2 меры на направление, несовместимости) и `calculateScenario` (эффекты с учётом лага,
  синергии, клиппинг 0–100, D_d, D_avg, N_crit, итоговый Score по формуле раздела 3 датасета).
  Числа не округляются в расчётах — округление только при отображении.
- `src/lib/improve.ts` — поиск улучшения сценария одной заменой одного из пяти решений
  (использует только `calculateScenario`/`validateScenario`, не дублирует формулу).
- `src/lib/explain.ts` — AI-объяснение уже посчитанного результата: реальный вызов LLM (OpenAI,
  ключ только на сервере) с детерминированным офлайн-шаблоном на тех же цифрах как резерв, если
  ключ не задан или API недоступен.
- `src/app/api/scenario`, `/api/explain`, `/api/improve` — серверные роуты; сценарий всегда
  пересчитывается на сервере (клиенту не доверяем).
- `src/components/Simulator.tsx` — интерфейс: выбор мероприятий по направлениям, счётчик
  бюджета/решений, причины невалидности, результат до/после по районам, AI-анализ, «Улучшить одной
  заменой».
- `CONTRACT.md` — контракт между частями системы и разделение ответственности внутри команды.

ИИ используется только для объяснения уже рассчитанных чисел (сравнение сценариев, сильные
стороны, риски, рекомендации) — сам Score считается детерминированно по формуле, без участия LLM.

## Установка и запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Приложение откроется на [http://localhost:3000](http://localhost:3000).

Продакшн-сборка:

```bash
npm run build
npm run start
```

## Переменные окружения

Создайте `.env.local` в корне проекта (уже в `.gitignore`, ключи туда не попадают):

```bash
OPENAI_API_KEY=sk-...       # для реального AI-анализа через OpenAI
# или
ANTHROPIC_API_KEY=sk-ant-...  # альтернативный провайдер (Claude)

# необязательно, значения по умолчанию:
OPENAI_MODEL=gpt-4o
ANTHROPIC_MODEL=claude-sonnet-5
```

Без ключей приложение полностью работает: расчёт Score не требует LLM, а AI-анализ автоматически
переключается на офлайн-объяснение по шаблону на реальных посчитанных цифрах (это не выдаётся за
ответ модели — в интерфейсе явно указан источник: «GPT (OpenAI API)», «Claude (Anthropic API)» или
«офлайн-шаблон»).

## Проверка корректности расчёта

```bash
npm run verify
```

Скрипт `src/lib/verify.ts` сверяет движок с контрольными значениями из датасета и с чек-листом
граничных случаев:

- Базовый сценарий без решений: Score = 52.56 (D_avg 56.86, худший район Нура 49.18, 2 критических
  показателя).
- Пример из раздела 3 датасета (M7, M8, M10 в Нуре + M12 город + M5 в Сарыарке): стоимость 95,
  Score ≈ 56.54 (+3.99 к базе), синергия M10+M12 срабатывает.
- Самый дешёвый допустимый набор (M9, M11, M10, M12, M4 в Нуре): стоимость 61.
- Невалидные наборы: 4 или 6 решений, повтор мероприятия, бюджет > 100, 3 меры одного направления,
  конфликт M1/M3 (в любых районах), конфликт M4/M7 и M5/M13 (только в одном районе) — все корректно
  отклоняются с объяснением причины.
- Порядок решений не влияет на итоговый Score.

## Как проверить сценарий вручную

1. Откройте приложение, выберите ровно 5 мероприятий (для «районных» — укажите район).
2. Бюджет и счётчик решений в шапке показывают остаток и превышение в реальном времени; при
   нарушении правил (бюджет, повтор, несовместимость, >2 меры одного направления) появляется
   объяснение причины вместо Score.
3. При валидном наборе из 5 решений ниже появляется Astana Quality of Life Score, разбивка по
   районам «до/после», сработавшие синергии и число критических показателей.
4. Кнопка «Получить AI-анализ решения» — реальный вызов LLM с уже посчитанными числами.
5. Кнопка «Улучшить одной заменой» — предлагает лучшую найденную допустимую замену одного решения
   (или честно сообщает, что улучшений не найдено).

## Ограничения MVP

- Датасет синтетический и фиксированный (без БД), сценарий пользователя хранится в браузере —
  это осознанное упрощение для хакатона, а не недоработка.
- `findBestSingleSwap` перебирает только замену одного из пяти решений, а не глобальную
  оптимизацию всего набора.
