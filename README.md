# Аким на 5 часов — AI-симулятор управления городом

Команда **Tofifidrinkers** (`hack-f9ef362b-tofifidrinkers`). Хакатон HackAlem AI, спец-трек
**Astana Innovations**. MVP: распределить фиксированный виртуальный
бюджет (100 у.е.) между 5 районами, принять ровно 5 управленческих решений и получить итоговый
**Astana Quality of Life Score** с AI-объяснением.

> Данные синтетические. Результат — оценка внутри учебной модели хакатона, а не прогноз реальных
> последствий для Астаны.

## Архитектура

Next.js 16 (App Router, TypeScript) — фронтенд и бэкенд в одном приложении.

- `src/lib/data.ts` — датасет: 5 районов, 10 показателей, 14 мероприятий, синергии, несовместимости,
  бюджет и веса. Перенесено из «Датасет районов.docx» без изменений цифр.
- `src/lib/engine.ts` — расчётное ядро: `validateScenario` (проверка правил, ровно 5 решений, бюджет,
  максимум 2 меры на направление, несовместимости) и `calculateScenario` (эффекты с учётом лага,
  синергии, клиппинг 0–100, D_d, D_avg, N_crit, итоговый Score по формуле раздела 3 датасета).
  Числа не округляются в расчётах — округление только при отображении.
- `src/lib/improve.ts` — поиск улучшения сценария одной заменой одного из пяти решений
  (использует только `calculateScenario`/`validateScenario`, не дублирует формулу).
- `src/lib/explain.ts` — AI-объяснение уже посчитанного результата: реальный вызов LLM (OpenAI
  или Anthropic, ключ только на сервере) с детерминированным офлайн-шаблоном на тех же цифрах как резерв, если
  ключ не задан или API недоступен.
- `src/app/api/scenario`, `/api/explain`, `/api/improve` — серверные роуты; сценарий всегда
  пересчитывается на сервере (клиенту не доверяем).
- `src/components/Simulator.tsx` — интерфейс: выбор мероприятий по направлениям, счётчик
  бюджета/решений, причины невалидности, результат до/после по районам, AI-анализ, «Улучшить одной
  заменой».
- `CONTRACT.md` — контракт между частями системы и разделение ответственности внутри команды.

ИИ используется только для объяснения уже рассчитанных чисел (сравнение сценариев, сильные
стороны, риски, рекомендации) — сам Score считается детерминированно по формуле, без участия LLM.

## Установка и запуск

Требуется Node.js 20.9+ и npm.

```bash
npm install
npm run dev
```

Приложение откроется на [http://localhost:3000](http://localhost:3000).

Продакшн-сборка:

```bash
npm run build
npm run start
```

## Переменные окружения

Для обычного расчёта, примера и советника переменные окружения не нужны.
Для ответа языковой модели создайте `.env.local` в корне проекта (файл исключён через `.gitignore`).
Задайте `OPENAI_API_KEY` или `ANTHROPIC_API_KEY` локально; не добавляйте ключи в код, коммиты и сообщения.
При наличии обоих ключей сервер сначала пробует Anthropic, затем OpenAI.

Названия необязательных настроек моделей и текущие значения по умолчанию:

```dotenv
OPENAI_MODEL=gpt-4o
ANTHROPIC_MODEL=claude-sonnet-5
```

Без ключей доступны выбор решений, валидация, расчёт, сравнение районов и советник: расчёт Score не требует LLM, а AI-анализ автоматически
переключается на офлайн-объяснение по шаблону на реальных посчитанных цифрах (это не выдаётся за
ответ модели — в интерфейсе явно указан источник: «GPT (OpenAI API)», «Claude (Anthropic API)» или
«офлайн-шаблон»).

## Проверка корректности расчёта

```bash
npm run verify           # контрольные числа датасета + чек-лист граничных случаев
npm run verify:daniyal   # 23 сценария, база и 6 граничных проверок команды
npm run verify:improve   # 73 проверки советника, включая перенос района и равенства Score
npm run lint
npm run build           # также проверяет TypeScript
npx tsc --noEmit        # отдельно после сборки, создавшей типы Next.js
```

Скрипт `src/lib/verify.ts` сверяет движок с контрольными значениями из датасета и с чек-листом
граничных случаев:

- Базовый сценарий без решений: Score = 52.56 (D_avg 56.86, худший район Нура 49.18, 2 критических
  показателя).
- Пример из раздела 3 датасета (M7, M8, M10 в Нуре + M12 город + M5 в Сарыарке): стоимость 95,
  Score ≈ 56.54 (+3.99 к базе), синергия M10+M12 срабатывает.
- Самый дешёвый допустимый набор (M9, M11, M10, M12, M4 в Нуре): стоимость 61.
- Невалидные наборы: 4 или 6 решений, повтор мероприятия, бюджет > 100, 3 меры одного направления,
  конфликт M1/M3 (в любых районах), конфликт M4/M7 и M5/M13 (только в одном районе) — все корректно
  отклоняются с объяснением причины.
- Порядок решений не влияет на итоговый Score.

## Демо: пример → рекомендация → применение

1. Нажмите **«Загрузить пример»**. Будут выбраны M7, M8 и M10 в Нуре,
   M12 для всего города и M5 в Сарыарке. Это обычные выбранные решения: интерфейс
   автоматически вызывает общий `calculateScenario`, а не подставляет готовый результат.
2. Проверьте стоимость **95**, исходный Score **52.56**, итоговый **56.54** и прирост **+3.99**.
   Неокруглённые ориентиры: 52.55768 → 56.54307. Прирост считается до округления.
3. В блоке «Улучшить одной заменой» нажмите **«Найти улучшение»**.
   `/api/improve` возвращает предложение заменить **M5 в Сарыарке** на **M3 в Нуре**:
   стоимость 95 → **100**, Score 56.54307 → **57.20556**, прирост **+0.66** на экране.
4. Нажмите **«Применить замену»**. Заменяется ровно решение с совпадающими `measureId`
   и `districtId`; остальные четыре сохраняются. Общий движок повторно проверяет
   допустимость и результат, выбранные карточки и итоговый Score обновляются вместе.
5. Нажмите **«Получить AI-объяснение»**. Интерфейс использует существующий `/api/explain`,
   показывает загрузку, готовый текст с источником либо ошибку с возможностью повторить запрос.
   Без ключа возвращается явно подписанный офлайн-шаблон, а не выдуманный ответ модели.
6. Измените любое решение или район: результат пересчитается, прежние советы и объяснения
   исчезнут. Оба запроса отменяются; номер редакции сценария дополнительно защищает от
   запоздавших ответов. Повторное нажатие во время загрузки не создаёт второй запрос.

Описанный советник реализован в текущем `src/lib/improve.ts`. Его `null` для допустимого
сценария означает: **«Среди допустимых замен одного решения улучшение не найдено»**.
Это локальный поиск по одной замене, а не доказательство глобально оптимального бюджета.
При переносе интерфейса на старую ветку с заглушкой советник должен быть обозначен как
временно недоступный: её `null` не означает, что улучшений нет.

### Ручные проверки ошибок и актуальности

- Сбросьте сценарий, выберите районное мероприятие и оставьте «Выберите район»:
  появится подсказка; итоговый Score не показывается до заполнения всех нужных районов.
- После загрузки примера уберите M12 и выберите M13: стоимость станет **109**,
  появится сообщение о превышении бюджета, результат и действия советника/AI исчезнут.
- Проверьте несовместимые мероприятия и больше двух мер одного направления:
  при пяти решениях общая валидация объясняет причину недопустимости.
- Во время загрузки объяснения или рекомендации измените район, загрузите пример
  повторно или сбросьте выбор. Старый ответ не должен появиться в новом сценарии.
- Для проверки сетевой ошибки после загрузки примера временно отключите сеть в инструментах
  браузера и запросите объяснение/совет. Верните сеть и повторите запрос.
- На узком экране карточки располагаются в одну колонку, таблица исходных данных
  прокручивается внутри своего блока. Элементы управления доступны с клавиатуры.

## Ограничения MVP

- Синтетический фиксированный датасет, без базы данных и прогнозирования реальных событий.
- Выбор хранится только в состоянии открытой страницы; после перезагрузки сбрасывается.
- `findBestSingleSwap` перебирает одну замену, а не глобально оптимизирует весь набор.
- Реальное AI-объяснение требует действующего ключа, доступной модели у провайдера и сети.
  Доступность внешних моделей не гарантируется; при ошибках сервер использует офлайн-шаблон.
- Интерфейс прекращает ожидание ответа через 30 секунд и предлагает повторить запрос.
- Сравнение нескольких сохранённых сценариев, рейтинг команд и генерация презентаций
  в этой версии не реализованы.
