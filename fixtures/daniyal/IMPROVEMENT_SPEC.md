# Улучшение сценария одной заменой

Статус: спецификация, код советника ещё не реализован. Использовать общий валидатор и общий расчёт Ильяса; не переносить проверочный скрипт в backend.

## Вход и результат
Вход — допустимый сценарий из пяти решений. Если он невалиден, вернуть причины и не искать улучшение.
Результат — исходная оценка, удалённое и добавленное решение, полный новый сценарий, его результат расчёта, изменение Score и стоимости. Точные названия полей согласовать с Ильясом.

## Перебор
1. Проверить исходный сценарий и рассчитать его общим модулем.
2. Для каждой из пяти позиций временно удалить решение.
3. Для каждого M1–M14 сформировать варианты: для районной меры — каждый из пяти районов, для городской — один вариант с districtId=null.
4. Исключить мероприятия, оставшиеся в других четырёх позициях. Прежняя мера разрешена для смены её района. Полностью неизменный вариант пропустить.
5. Собрать пять решений и вызвать общий валидатор; недопустимые варианты отбросить.
6. Вызвать общий расчёт, сравнить Score с исходным без округления для экрана.
7. Сохранить лучший кандидат только при строго положительном улучшении.
8. Для равных Score предпочесть меньшую стоимость. При равной стоимости выбрать лексикографически меньший канонический ключ сценария: решения отсортированы по числу после M, затем по districtId (null представлять пустой строкой).
9. Если улучшений нет: «Среди замен одного решения улучшений не найдено».

При Decimal проверять строго > 0; при float использовать согласованную погрешность (например 1e-8), чтобы шум вычислений не считался улучшением. Не считать разницу уже округлённых чисел.

Есть 10 районных и 4 городских мероприятия: 54 варианта решения, до 270 кандидатов до фильтрации и удаления дублей. Результат — лучший среди замен одного решения, не глобальный оптимум и не произвольное перераспределение всего бюджета.

## Проверки после реализации
- Невалидный вход не получает рекомендацию.
- Новый набор сохраняет все ограничения.
- Перенос меры в другой район рассматривается.
- Новая оценка совпадает с прямым вызовом общего расчёта.
- Предложение действительно улучшает результат с выбранной точностью.
- Нет улучшения: вернуть понятный статус, не подменять его случайным советом.
- Равенства разрешаются стабильно; перестановка входных решений не меняет итоговый набор.
- Исходный набор не изменяется при переборе.

LLM позднее может объяснить готовое сравнение. Числа, допустимость и выбор лучшего варианта определяет код.

## Что получить от Ильяса
Язык и версия; расположение модулей; согласованный формат решений; сигнатуры и синхронность валидатора и расчёта; формат ошибок и результата; способ получить базовый результат; стратегия точности чисел. До этого реализацию не привязывать к стеку.
