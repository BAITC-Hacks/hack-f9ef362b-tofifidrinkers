# Игра для жителей: границы интеграции

## Деньги

`MONEY_SCALE` в `presentation.ts` — единственная настройка перевода внутренних стоимостей в тенге. Предложение: **1 единица = 10 000 000 ₸**, общий учебный бюджет — **1 000 000 000 ₸**. Это не рыночные цены и не городская смета. `approved: false` оставлен до явного согласования; статус виден в интерфейсе на всех трёх языках. После согласования достаточно изменить эту настройку. Движок, каталог и API продолжают работать в исходных единицах.

## Действующий AI-контракт

`POST /api/explain` принимает `{ decisions }`, возвращает `{ explanation, source }`. `src/lib/explain.ts` задаёт русский язык ответа и формирует свободный текст с внутренними единицами стоимости. Игра этот контракт не меняет и не отправляет неподдерживаемые поля.

Данные о распределении расходов, изменениях районов, критических значениях и побочных эффектах выводятся детерминированно из текущих решений и ScenarioResult. Они доступны без AI на русском, казахском и английском. Это отдельный анализ данных, а не перевод или выдуманный ответ модели.

- При `offline-template` интерфейс честно сообщает о шаблонном объяснении и ссылается на локализованный анализ тех же результатов.
- При `openai` / `anthropic` ответ доступен в раскрываемом разделе с явной подписью «на русском» и `lang="ru"`.
- Финансовые абзацы свободного текста не пересчитываются по догадке и не показываются: типизированные суммы уже приведены в таблице. Числа индекса и показатели не умножаются на денежный коэффициент. Фильтр финансовой лексики консервативный, это временный слой представления, а не полноценная типизация ответа.
- Смена языка сохраняет план, результат и положение героя. Ответ, начатый до смены языка, остаётся ответом на тот же план и честно помечается русским.

## Минимальное расширение для ответственного за API (предложение, не реализовано)

1. Добавить необязательный `locale: "ru" | "kk" | "en"` в запрос `/api/explain` с совместимым значением по умолчанию `ru`; возвращать фактический `locale` в ответе.
2. Использовать структурированные секции объяснения: последствия, риски, компромиссы, проверенная рекомендация. Ссылки на деньги передавать как типизированные факты `{ kind: "money", units: number }`, на показатели — `{ kind: "indicator", indicatorId, value }`. В свободном тексте не дублировать денежные числа. Клиент самостоятельно форматирует валюту по MONEY_SCALE.
3. Дополнить вход модели вычисленной на сервере сводкой: расходы по пяти районам + общегородские отдельно, исходные/итоговые районные показатели, оставшиеся критические значения. Не пересчитывать Score моделью.
4. Пояснять концентрацию расходов с учётом исходных нужд; рекомендовать конкретные замены только после проверки движком. Критерий текущего советника — индекс, а не равенство районных бюджетов.
5. Для нового денежного масштаба и языка проверять шаблонный и AI-пути одинаковыми контрактными тестами. Не заменять данные движка ответом модели.

## Проверки игры

- `npx tsx --test src/components/game/world.test.ts`
- `npx tsc --noEmit` (после сборки Next генерирует LayoutProps)
- `npx eslint .`
- `npm run build`
- Существующие `npm run verify`, `npm run verify:improve`, `npm run verify:explain`.

Ручной путь: `/game` → Нура → изучить проект → подтвердить / отменить → загрузить пример → последствия → советник → применить → объяснение. Во время этого пути менять язык, проверять сохранение состояния, движение клавишами относительно экрана и мобильную панель.
